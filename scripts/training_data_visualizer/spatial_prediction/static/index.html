这个数据集是什么（和 tasks/spatial_prediction.py 的约定一致）：

  • 一个样本 = 一帧：ctx_player (10,20) + 逐帧武器 + 两两遮挡 + 道具 + 全局状态。输入侧和 aim 逐列一致，只是没有 257 帧的窗口。
  • 一个 npz = 一个回合里被随机抽到的 K 帧（文件名末尾的 _n{K}）。抽帧是 demo 级的：T / density 帧在整局上 均匀随机选，所以同一个文件里的第 k 行要比第 k-1 行晚（按时间升序）。
  • 5 个标签都是"这一帧之后"（严格 i > t，不含当前帧）： ct_win / alive_end / can_kill / next_death / next_kill。后两个是11 类： 0..9 是玩家下标，10 表示本回合不会再有了 —— 它是一个 有信息量的类别，训练侧直接 CE，不用掩码。
  • next_death / next_kill 满足「当事人当前帧还活着」。 页面上如果出现「标签里的人当帧是死的」警告，那是造数 / 切片的问题，不是前端。
  • 角度：文件里存的是 sin/cos 四列（yaw 在 ±180 会跳变，模型插值不了）， 这里用 atan2 还原成度。眼高 = z + 64.0938 − 18·crouch。
  • ctx_player_mask 是真 bool（True = 这一帧活着），所以 to_torch() 会把它变成 torch.bool，可以径直当 key_padding_mask 用；队伍在 ctx_player_team （0 = CT / 1 = T / -1 = 未知），死人也保留队伍 —— "哪队"和"死没死"是两个正交的量。 ctx_player 第 15 列虽然也是 team，但它是 [0,1] 浮点，-1 会被压成 0， 别拿它判队伍。
